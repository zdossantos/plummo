# Barèmes et session — plan d'implémentation

> Exécution avec superpowers:executing-plans ; tests avec superpowers:test-driven-development.

**Objectif :** centraliser les scores validés et permettre au chef de choisir l'objectif, prolonger ou recommencer avec un classement global visible.
**Spécification :** `docs/metier-plummo.md`, section 4.
**Contraintes :** Laravel, PHP 8.4, Bun 1.3.14, FR/EN, seuls tests sur plummo_testing. Aucun endpoint d'attribution libre de points.

## Tâche 1 — Barème pur

Créer `app/Services/Scoring.php` et `tests/Unit/ScoringTest.php`.
Interfaces : `rapid(int $participants, int $rank, int $tied = 1): int`, `artist(int $guessers, int $found): int`, `votes(int $count): int`.

- [x] Tester effectifs 1–8, rangs publiés, égalités, arrondis, absence de devineur et arguments invalides ; observer le RED.
- [x] Implémenter la formule validée ; les égalités moyennent les points entiers des places occupées puis arrondissent vers le haut à mi-chemin.
- [x] Vérifier `php artisan test --compact tests/Unit/ScoringTest.php` : GREEN.

## Tâche 2 — Session et classement

Migration `rooms.point_target` entier nullable par défaut 1000. `SessionController` autorise uniquement le chef connecté : PATCH /rooms/CODE/session avec action configure/extend/restart, target nullable ou entier positif, extra entier positif pour prolongation ; restart exige confirmation et remet tous les scores à zéro. Extension = meilleur score conservé + extra. Pas de publication d'un endpoint qui attribue des points.
Le snapshot public fournit target et classement de tous les joueurs conservés, avec rang partagé en cas d'égalité. Réutiliser les avatars et noms ; la liste des places demeure distincte.

- [x] Tests HTTP d'autorisations, configuration, extension depuis le score réel, restart confirmé et conservation des identités, classement des joueurs partis ; observer le RED.
- [x] Implémenter migration, contrôleur et état ; vérifier le GREEN.
- [x] Présenter l'objectif et le classement sur grand écran, les réglages sur téléphone du chef, traductions FR/EN et confirmation de remise à zéro.
- [x] Vérifier les contrôles du README et un parcours navigateur ; revue indépendante, commit, PR, CI puis fusion.

Débordement du score/objectif MySQL, tableau au lieu d'entier, chef déconnecté, doublons de pseudos, scores des joueurs partis et actualisation du formulaire pendant un changement du chef.
